# ATOTO X10: X10 ADB Doctor

The original app only works on FYT head units (ATOTO S8): it binds
`com.syu.ms/app.ToolkitService` and sends FYT command 161 to set the ADB port.
The X10 (X10G211E, Android 13) is a Qualcomm QCM6125 (qti/trinket) unit, so
that service is missing and the app reported the firmware as incompatible.

A normal Android 13 app cannot switch ADB on by itself. X10 ADB Doctor looks
for a route the firmware already offers and reports what it finds.

## What it does

- **Verdict** at the top: ADB already on (with the `adb connect` line), Wireless
  debugging on, a Developer options screen to try, the FYT route, or "no
  supported route found".
- **Open Developer options**: launches Settings' Developer options page directly
  (the action, then the Settings activities by name). This page often opens
  even when tapping Build number is blocked; turn on **Use developer options**,
  then **Wireless debugging**.
- **Screens found on this unit**: buttons for exported activities in vendor and
  Settings packages whose names suggest developer, debug, ADB, factory or
  engineering screens. Tap to try; each result goes in the action log.
- **FYT: ADB on until reboot**: only shown if `com.syu.ms` exists (S8 route).
- **Report**: device and build, ADB settings and properties, user restrictions,
  IP addresses, port probes (5555 and the Wireless debugging port), vendor
  packages with their exported activities and services, `service list`, all
  installed packages and all readable system properties.

## Getting the report off the unit

- While the app is on screen it serves the report on the local network:
  `curl http://HEAD_UNIT_IP:8765 > x10-report.txt` from the laptop or the Pi.
  It stops when the app leaves the screen.
- Or **Share report** / **Copy report**.

## Install

Download the `x10-adb-doctor` artifact from the latest successful run on the
Actions tab, unzip it, and copy `x10-adb-doctor.apk` to the head unit (USB
stick, or serve it from the laptop or Pi and open it in the head unit's
browser). Allow installs from that app when asked. Each build is debug-signed
with a new key, so uninstall the previous X10 ADB Doctor before installing a
newer build.

## Safety

ADB gives a paired computer full control of the head unit. Use it only on a
trusted network, approve the RSA prompt on the screen yourself, and turn it off
when it is not needed. The app does not root, patch or change the unit; it
only reads and launches screens that the firmware already exposes.
